## 🤔 Зачем это нужно?

Поднять L2TP/IPSec вручную — значит часами разбираться в конфигах strongSwan, xl2tpd и ppp, вручную настраивать NAT, sysctl и systemd-сервисы. Этот скрипт делает всё сам:

- 🔐 **IPSec + L2TP** — strongSwan и xl2tpd устанавливаются и настраиваются полностью
- 🧑‍💻 **Пользователи** — добавление, удаление, смена паролей через удобное меню
- 🌐 **NAT и firewall** — iptables настраивается автоматически, правила восстанавливаются после перезагрузки
- 🔒 **Безопасность** — современные шифры AES-256, без 3DES и слабых DH-групп
- 📋 **Совместимость** — Windows, macOS, iOS, Android из коробки

## ✨ Возможности

### 🔐 VPN-сервер

| Компонент | Детали |
| --- | --- |
| **IPSec** | strongSwan, IKEv1, Pre-Shared Key |
| **L2TP** | xl2tpd, PPP/CHAP, MS-CHAPv2 |
| **Шифрование** | AES-256-SHA2, DH modp2048/modp1536 |
| **Подсеть** | Выбор из предустановленных или своя /24 |
| **DNS для клиентов** | Cloudflare, Quad9, Google, AdGuard, OpenDNS, Yandex или свой |

---

### 🧑‍💻 Управление пользователями

- Добавление с автогенерацией пароля (20 символов, `/dev/urandom`)
- Удаление — немедленный отзыв доступа
- Смена пароля — вступает в силу при следующем подключении
- Список пользователей с паролями

---

### 🔥 Firewall и сеть

| Правило | Описание |
| --- | --- |
| UDP 500 | IKE (согласование IPSec) |
| UDP 4500 | NAT-T (IPSec за NAT/роутером) |
| UDP 1701 | L2TP-туннель |
| ESP / AH | Инкапсуляция и аутентификация IPSec |
| MASQUERADE | NAT для выхода клиентов в интернет |

Правила автоматически восстанавливаются после перезагрузки через systemd-сервис.

---

### 🛡️ Безопасность

| Параметр | Значение |
| --- | --- |
| PSK | 32 символа, только `A-Za-z0-9`, `/dev/urandom` |
| Пароли пользователей | 20 символов, спецсимволы, `/dev/urandom` |
| `ipsec.secrets` | chmod 600, владелец root |
| `chap-secrets` | chmod 600, владелец root |
| Шифры IKE | aes256-sha2_256-modp2048, aes256-sha1-modp2048 |
| Шифры ESP | aes256-sha2_256, aes256-sha1 |
| Исключено | 3DES, DH group 2 (modp1024) |

## 📁 Что создаётся в итоге

```
/etc/xl2tpd/xl2tpd.conf                       # Конфиг L2TP-демона
/etc/ipsec.conf                               # Профили IPSec
/etc/ipsec.secrets                            # Pre-Shared Key (chmod 600)
/etc/ppp/chap-secrets                         # Пользователи VPN (chmod 600)
/etc/ppp/options.xl2tpd                       # PPP-опции (DNS, MTU, auth)

/etc/l2tp-menu/
├── users                                     # Реестр пользователей
└── credentials.txt                           # Параметры подключения (chmod 600)

/etc/iptables/l2tp-rules.sh                   # Скрипт правил iptables
/etc/systemd/system/iptables-l2tp.service     # Автозапуск правил после ребута
/etc/sysctl.d/99-l2tp-ipsec.conf              # ip_forward и защита от редиректов

/var/log/l2tp-menu/l2tp-install.log           # Лог установки пакетов
```

## 📱 Подключение клиентов

После установки скрипт выводит параметры подключения. Они также сохраняются в `/etc/l2tp-menu/credentials.txt`.

### Windows

Пуск → Параметры → Сеть и Интернет → VPN → Добавить VPN  
Поставщик: **Windows (встроенный)** · Тип: **L2TP/IPSec с общим ключом**

### macOS / iOS

Настройки → VPN → Добавить конфигурацию → **L2TP**

### Android

Настройки → Сеть → VPN → Добавить → **L2TP/IPSec PSK**

## 🔐 Безопасность реализации

Скрипт написан с акцентом на надёжность:

- **Проверка статуса IPSec через `if`-блок** — исключает ложные результаты из-за одинакового приоритета операторов `||` и `&&` в Bash
- **Безопасный `remove_sysctl`** — при удалении VPN `ip_forward` не сбрасывается принудительно, чтобы не сломать Docker и другие сервисы
- **Systemd-юнит iptables** — `After=network.target` гарантирует, что правила применяются после поднятия интерфейсов
- **Современные шифры** — только AES-256 + modp2048 и выше; 3DES и DH group 2 исключены
- **Все пути через константы** — пути к конфигам объявлены в начале скрипта, нет захардкоженных дублей

**v1.0 — текущая версия**
